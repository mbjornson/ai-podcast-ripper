# Successfully coding with AI in large enterprises: Centralized rules, workflows for tech debt, and training your team | Zach Davis (Director of Engineering at LaunchDarkly) — How I AI

## Summary
The episode discusses how large enterprises can successfully integrate AI agents into complex engineering workflows without resorting to unstructured "vibe coding." Zach Davis, Director of Engineering at LaunchDarkly, argues that while individual developers can achieve high commit counts on personal projects, this approach is unsustainable and dangerous when dealing with mission-critical platforms that power massive global experiences. The core thesis is that successful AI adoption requires treating the codebase itself as a highly structured asset.

Davis outlines a systemic approach to make tools like Cursor and Devin reliable by default. Instead of letting every tool operate with isolated rule sets (e.g., `.cursorrules`, `.cloudmd`), he implemented a centralized knowledge base within the repository, consolidating all guidelines—from JS style guides to TypeScript essentials—into one master file (`.agents_rules`). This centralization ensures that both human engineers and LLMs have access to a single source of truth, making the entire system scalable and predictable.

## Key Points
- **Vibe Coding is an Enterprise Risk:** "Vibe coding is not an acceptable enterprise development strategy." For large platforms, unstructured individual developer workflows cannot be scaled or maintained due to quality, documentation, and consistency issues.
- **The Centralized Rules Protocol:** The most significant technical takeaway is the need for a single, consolidated rules protocol (e.g., `.agents_rules`) that all AI tools point to. This eliminates tool fragmentation and makes the system scalable across multiple LLM agents.
- **Documentation as an API:** Instead of storing documentation in external systems like Confluence or Google Docs, critical guidelines (front end organization, accessibility, JS style guides) must be embedded directly into a dedicated `docs` directory within the repository. This ensures immediate access for both human developers and AI models.
- **Operationalizing Change:** Successful adoption requires more than just buying tools; it demands organizational structure. A designated person or role must be responsible for driving the transformation, acting as an internal champion who can test, validate, and enforce best practices across the engineering team.
- **The Goal of "Aha" Moments:** The operational objective is to design the system so that skeptical engineers have a positive first experience with AI tools (the "aha moment"), rather than encountering initial failures that lead to rejection.

## Tools & Resources
- **AI Development Tools Mentioned:** Cursor, Devin, Copilot (for code review), Augment, V0, Figma Make, ChatPRD.
- **Enterprise Feature Layer:** WorkOS (Positioned as "Stripe for enterprise features," helping apps achieve secure authentication, access controls, and audit logs necessary for large corporate adoption).

## Action Items
- [ ] **Systemize Knowledge:** Audit your current company documentation (Confluence, Google Docs) and migrate the most critical, frequently referenced guidelines into a single, dedicated `docs` directory within your primary codebase repository.
- [ ] **Consolidate Rulesets:** Identify all disparate rules or style guides used by different tools/departments (e.g., PR checklists, coding standards). Consolidate these into one master "Agents Rules" file and have all sub-tools reference this single source of truth.
- [ ] **Design for Success:** When introducing a new technology or process to a team, do not simply deploy the tool. Instead, build a structured onboarding path that guarantees early success ("the aha moment") for skeptical users.
- [ ] **Define an AI Champion Role:** If your company is considering large-scale AI adoption, formally designate one person (a "Director of Engineering" equivalent) whose primary responsibility is to test, validate, and operationalize the integration of these tools across the entire engineering organization.
