# Gemini 3 vs. Claude Opus 4.5 vs. GPT-5.1 Codex: Which AI model is the best designer? — How I AI

## Summary
The episode is a technical deep dive comparing the design and functionality capabilities of three cutting-edge AI models: Gemini 3 Pro (Google), Opus 4.5 (Anthropic), and GPT-5.1 Codex (OpenAI). The host, Claire Vo, a product leader and AI enthusiast, set up a controlled experiment by giving all three models the same prompt—to redesign an existing, poorly structured blog page—and asking them to improve both visual appeal and user experience (UX), while also integrating best practices for SEO and navigation. The discussion moves beyond simple "one-shot" generation, focusing instead on which model acts as a true "design engineer" capable of thoughtful, functional improvements to existing codebases.

The core finding is that while all three models are highly capable, Opus 4.5 demonstrated superior performance. Its ability to generate a structured, step-by-step plan (a "to-do list" or tool call) before executing the code was the critical differentiator. This methodical planning allowed it to incorporate subtle, high-quality design tweaks, better asset management, and more comprehensive SEO structures than its competitors.

## Key Points
- **Planning > Execution:** The most significant insight is that the model's ability to plan its implementation (e.g., Opus 4.5 generating four distinct to-do list items) is more valuable than its ability to simply generate beautiful code in a single shot. Structured planning leads to more comprehensive, functional outcomes.
- **The Power of Subtle Detail:** Opus 4.5 excelled by adding "edge touches" that elevate the design, such as using placeholder icons for missing assets (making the page look professional even when content is absent) and adding subtle, functional hover effects (like the call-to-action arrow).
- **SEO and Functionality Depth:** Opus 4.5 provided superior SEO implementation, including structured data, canonical URLs, and meta tags, while also adding functional elements like estimated reading time and author links—details that went beyond basic visual redesign.
- **The Flaw of Generic Output:** GPT-5.1 Codex, while strong in copywriting, failed on the design front, generating generic "AI slop" aesthetics (e.g., purple gradients) and lacking clear user experience context or calls to action, suggesting that high-level coding capability does not guarantee high-level design judgment.
- **The "Design Engineer" Metric:** The test established that the best AI model is not the one that makes something *look* beautiful, but the one that acts like a thoughtful, iterative design engineer who can improve functionality and structure systematically.

## Action Items
- [ ] **Develop Structured Prompting:** When using AI for complex tasks (design, business plans, code), force the model to generate a detailed, numbered "Plan" or "To-Do List" *before* asking it to execute the final output. This mimics the planning phase of a human expert.
- [ ] **Test AI for Functional Flaws:** Don't just ask AI to make something look good; specifically prompt it to address functional gaps (e.g., "Add placeholder assets for missing images," or "Ensure this design accounts for empty data states").
- [ ] **Prototype with Lovable:** If you have a business idea, use Lovable to move past static mockups and build a functional, deployable prototype over a weekend.
- [ ] **Focus on Planning Capabilities:** When evaluating AI tools, prioritize models that demonstrate advanced reasoning and tool-calling capabilities (like Opus 4.5's planning mode) over those that only provide immediate, beautiful code dumps.
