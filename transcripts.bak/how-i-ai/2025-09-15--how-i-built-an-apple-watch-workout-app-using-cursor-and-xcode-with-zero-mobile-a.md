# How I built an Apple Watch workout app using Cursor and Xcode (with zero mobile-app experience) — How I AI

## Summary
The episode details how the guest built a multi-device fitness tracker called Copper's Corner, solving the friction point of manually logging gym workouts. The core innovation is allowing users to simply speak their workout routine—e.g., "dumbbell shrugs 35 pounds 10 reps"—and having the system automatically process this voice input into structured data and analytics. This eliminates the need for traditional methods like notebooks or notes apps, making fitness tracking seamless across both iPhone and Apple Watch.

The discussion highlights a powerful modern development workflow: using AI tools (specifically Cursor) to bridge the gap between product ideation and native mobile app execution in Xcode. The guest's journey started with a simple Python script feeding GPT-4o into an Excel sheet, but quickly hit the limitation of unstructured data. This forced an upgrade to a full database backend, demonstrating that initial hacks are crucial for identifying technical scaling needs.

The episode provides valuable insights not only on product development (PM/Dev workflow) but also on leveraging AI for personal optimization. The ability to track consistency over 7, 30, and 90 days by simply narrating one's routine transforms the app from a simple logger into a powerful behavioral analytics tool.

## Key Points
- **Voice-to-Structured Data Pipeline:** The primary hack is using voice recording (via GPT Mobile App/Apple Watch) to capture workout data, which is then processed and tagged by an LLM into structured, quantifiable records (exercise name, weight, reps). This shifts the logging process from manual input to natural language narration.
- **Multi-Device Consistency:** The app syncs seamlessly across both iPhone and Apple Watch, ensuring users can log workouts regardless of whether they have their phone immediately accessible at the gym.
- **The Data Structure Upgrade Path:** The development process moved from a simple MVP (GPT -> Excel/unstructured text) to requiring a robust database backend with foreign keys. This illustrates that initial "hacky" solutions are excellent for validating concepts but will inevitably reveal the need for structured data architecture for true scalability and analytics.
- **AI Development Workflow ("Dual Wielding"):** The guest uses a side-by-side workflow, having Cursor generate code and then using Xcode for native building and debugging. This is necessary because mobile development requires deep integration with platform-specific tools (like the iOS simulator) that AI cannot fully replicate yet.
- **Product Development Cycle:** The recommended process for utilizing AI in product creation involves three stages: 1) Creating a detailed Product Requirements Document (PRD), 2) Having an AI model review and refine the PRD, and 3) Executing the build based on the refined plan.

## Tools & Resources
- **Cursor:** An AI-powered IDE used for generating code snippets and accelerating development within complex environments like Xcode.
- **Xcode:** Apple's native Integrated Development Environment (IDE), mandatory for building iOS and watchOS applications, especially when debugging compile/build errors.
- **GPT Mobile App / GPT-4o:** Used as the initial data capture mechanism (speech-to-text) and later for processing raw text into structured data sets.
- **Python Scripting:** Mentioned as the starting point for the MVP, demonstrating how basic scripting can bridge early functionality gaps before a full app build.
- **Paragon:** A B2B platform mentioned by the sponsor read, useful for accelerating product integration roadmaps (e.g., connecting Google Drive, Salesforce, etc.) in enterprise SaaS products.

## Action Items
- [ ] **Develop Voice Logging MVP:** Implement a prototype using your phone's voice recorder + GPT-4o/Claude API to capture unstructured data (e.g., notes, meeting summaries) and force it into a structured JSON format for immediate use (e.g., in Notion or Airtable).
- [ ] **Master the AI Development Loop:** Practice "dual wielding" an advanced LLM coding assistant (like Cursor) with a native IDE (Xcode/Android Studio) to understand where the AI excels (drafting code) and where human debugging is critical (build errors, platform limitations).
- [ ] **Build Structured Data First:** When planning any personal tracking system (fitness, reading, spending), do not start by building the UI. Start by defining the necessary database schema (the foreign keys and relationships) to ensure data consistency from Day 1.
- [ ] **Focus on Behavioral Analytics:** Use your chosen logging tool not just to record *what* happened, but to calculate trends over time (7/30/90 day views). The value is in the pattern recognition, not the raw input.
