# “I haven’t written a single line of front-end code in 3 months”: How Notion’s design team uses Claude Code to prototype — How I AI

## Summary
This episode features Brian Levin, a designer at Notion AI, discussing how the company’s design team utilizes Claude Code to rapidly prototype B2B SaaS designs. The core idea is to move design closer to production by creating a “prototype playground” – a Next.js app where designers can quickly experiment with ideas and iterate on designs in a realistic browser environment. Levin emphasizes the value of encountering reality early in the design process, highlighting the frustrations of traditional prototyping methods. The episode pivots to discuss the broader challenges of enterprise AI tools, particularly concerning security and access to company systems, and introduces Work OS as a solution for streamlining enterprise-ready AI integrations.

## Key Points
- **Rapid Prototyping:** Notion’s design team is leveraging Claude Code to drastically reduce prototyping time, moving from scribbled napkins to functional prototypes within the browser in minutes.
- **Reality Encounter:** Levin’s philosophy centers on encountering design realities (loading states, screen size issues) as early as possible, leading to faster and better designs.
- **Prototype Playground Setup:** The playground is a simple Next.js app with a directory structure mirroring the team’s designers, allowing for easy visibility and idea sharing. It’s designed to minimize global layouts and dependencies.
- **Code Yoinking:** Designers can “yoink” ideas from other prototypes, streamlining the iterative process and reducing redundant work.
- **Enterprise AI Challenges:** The episode highlights the significant hurdles faced by enterprise AI tools – namely, the need for deep system access, raising security concerns and triggering intense IT scrutiny.
- **Work OS Solution:** Work OS is presented as a solution, offering drop-in APIs that enable AI tools to seamlessly integrate with enterprise systems, addressing security and scalability concerns.
- **Technical Adept Team:** While the playground is built with Next.js, the design team is largely technically adept, with some individuals using it as their first foray into code-based prototyping.
- **External Prototype Linking:** The team has implemented a feature allowing designers to link external prototyping tools (Figma, etc.) to the playground, increasing flexibility.

## Tools & Resources
- **Next.js:** The JavaScript framework used for the prototype playground.
- **Claude Code:** The AI coding tool used for rapid prototyping.
- **Work OS:** A platform providing enterprise-ready APIs for AI tools. (https://www.workos.com/)
- **Vercel:** The platform used to deploy the prototype playground.
- **Figma/Other Prototyping Tools:** Designers are still utilizing these tools alongside the playground for specific tasks.
