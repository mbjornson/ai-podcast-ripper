# A 3-step AI coding workflow for solo founders | Ryan Carson (5x founder) — How I AI

## Summary
The episode details a structured, advanced AI coding workflow designed for solo founders and product builders who want to move beyond simple, unstructured "vibing" with generative AI. The guest, Ryan Carson—a five-time founder with two decades of experience—emphasizes that the biggest mistake in using AI is failing to provide sufficient context, leading to rushed or incomplete outputs. He presents a methodical process for translating high-level product ideas into executable code tasks by treating the AI less like a magic wand and more like a highly capable but directionally challenged junior developer.

The core methodology involves three distinct steps: first, formalizing the idea into a Product Requirement Document (PRD); second, using that PRD as the sole context for subsequent prompts; and third, generating detailed, step-by-step task lists directly from the finalized PRD. This structured approach ensures that the AI output is not just creative, but scalable and actionable, allowing an individual founder to manage complex product development tasks efficiently.

## Key Points
- **The Context Trap:** The single most critical piece of advice is to slow down and dedicate time to structuring context for the AI. Rushing this step significantly degrades the quality and utility of the output.
- **PRDs as the Single Source of Truth (SSOT):** Instead of prompting the AI with a vague goal, first generate a comprehensive PRD. This document acts as the foundational blueprint that all subsequent coding/task generation must reference.
- **Instructing the AI's Persona:** When writing prompts or rules for the AI, don't just state the task; define the audience and capability level. For example, instructing the AI to write a PRD "suitable for a junior developer" forces it to maintain a specific, digestible level of detail.
- **The Workflow Sequence (PRD $\rightarrow$ Tasks):** The process is linear: Use specialized rules/prompts in an agent mode (like Cursor) to generate a detailed PRD markdown file. Then, use *that* generated PRD as the context for a second set of prompts designed specifically to output a structured task list.
- **Advanced Tooling:** Utilizing tools like Cursor (a VS Code fork with AI integration) and specialized rules files allows users to automate complex documentation generation that previously required dedicated product managers or technical writers.

## Tools & Resources
- **Cursor:** A VS Code fork optimized for coding with AI, used in the demonstration for its "agent mode" capabilities.
- **ChatPRD:** An AI co-pilot tool designed specifically to help users write great product documentation (PRDs) and receive strategic coaching from an expert AI CPO.
- **Task Master:** Mentioned as a free, open-source command line interface (CLI) alternative for managing tasks generated by the workflow.
- **LLMs Used:** Claude 3.7 Sonnet and Gemini 2.5 Pro (The speaker notes using "max mode" on these models).

## Action Items
- [ ] **Skill Development:** Master structured prompting by defining both the *goal* and the *audience/persona* for the AI (e.g., "Act as a senior architect explaining this feature to a junior developer").
- [ ] **Business Process:** Implement a mandatory PRD step before writing any single line of code or generating task lists, regardless of how small the feature is.
- [ ] **Tools to Try:** Experiment with AI coding assistants like Cursor and dedicated product documentation tools such as ChatPRD.
- [ ] **Workflow Practice:** Create three specialized prompt rules (using a local LLM environment) that guide the AI through: 1) Feature Definition $\rightarrow$ 2) PRD Generation $\rightarrow$ 3) Task Breakdown List.
