# Claude Opus 4.6 vs. GPT-5.3 Codex: How I shipped 93,000 lines of code in 5 days — How I AI

## Summary
The episode provides a deep, technical comparison of the latest AI coding models, including OpenAI's Codex (and GPT-5.3) and Anthropic's Opus 4.6. The speaker, Claire Bowe, approaches model evaluation by testing them on a complex, established codebase (a multi-page marketing site) rather than simple, isolated "one-shot" tasks. This methodology is crucial because real-world AI application requires deep integration into existing company systems.

A major theme is the gap between AI's technical capability and its practical application in an enterprise setting. While the models are highly capable, they are often "too literal." This means they excel at following explicit instructions but struggle with "green field" or genuinely creative, broad architectural work. For AI to move from a novelty to a core business asset, it must be framed within robust, enterprise-grade workflows that handle security, access controls, and complex versioning.

## Key Points
- **Enterprise AI Requirement:** For AI tools to be adopted in large organizations, they must solve serious security concerns (authentication, access controls, audit logs). This necessity requires specialized platforms like Work OS, which provides "drop-in APIs for enterprise features," positioning it as "Stripe for enterprise features."
- **Advanced Testing Methodology:** The speaker rejects simple landing page redesigns, opting instead to test models on an existing, complex codebase. This simulates real-world development where the AI must operate within established architectural constraints.
- **Codex's Framework Focus:** OpenAI's Codex is designed around formal software engineering concepts, making Git primitives (Repositories, Branches, Work Trees, Diff, Pull Requests) first-class citizens in the UI. This structure is beneficial both for highly technical users and for those learning Git concepts.
- **Structured AI Workflows:** Codex introduces two key concepts for managing AI output: **Skills** (a package set of prompts, instructions, and reference files for consistent task execution) and **Automations** (tasks that can run on a schedule).
- **The "Literal" Caveat:** The primary critique of the models is their tendency to be overly literal. While this is a feature (reliable instruction following), it is a bug when the task requires creative, broad, or architectural leaps, making the conversational back-and-forth process slower and more painful than anticipated.

## Tools & Resources
- **Codex (OpenAI):** A desktop application for AI engineering, heavily focused on integrating Git primitives and structured workflows.
- **Work OS:** A platform providing "drop-in APIs for enterprise features" to make AI applications enterprise-ready and scalable.
- **GPT-5.3 Codex / Opus 4.6:** The specific models being compared, representing the cutting edge of coding AI.
- **GitHub Desktop:** Recommended as a visual tool for managing code changes across branches and files, useful for understanding the concepts Codex implements.

## Action Items
- [ ] **Adopt Structured AI Workflows:** When using generative AI for coding or business processes, don't rely on single prompts. Instead, define the task using structured "Skills" (a defined package of instructions/references) and schedule it using "Automations."
- [ ] **Master Git Primitives:** For technical roles, move beyond basic commits. Understand and utilize advanced concepts like **Work Trees** (full copies of a codebase for parallel agent work) and **Pull Requests** as a formalized signal for code readiness.
- [ ] **Focus on Enterprise Readiness:** If building an AI product, prioritize the non-functional requirements (security, audit logs, access controls) over the core functionality. Use specialized platforms (like Work OS) to handle the "enterprise lift."
- [ ] **Shift Prompting Strategy:** When using AI for complex redesigns or architecture, frame the prompt not just as a command ("Redesign this"), but as a constraint-based problem ("Redesign this, adhering to these three existing architectural rules, and optimizing for this specific user segment").
