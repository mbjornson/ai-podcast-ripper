# Claude Opus 4.8 is here. Is it as good as they say? — How I AI

## Summary
The episode provides an early, deep-dive technical review of Anthropic's latest model, Claude Opus 4.8, conducted by product leader Claire Vo. The discussion centers on whether this new iteration lives up to its hype as a state-of-the-art agent model. Vo’s overall assessment is nuanced: while Opus 4.8 is incredibly fast, efficient, and excellent for generating *greenfield* prototypes and one-shot tasks, it exhibits significant weaknesses when dealing with complexity, existing codebases, or high-level strategic context.

Vo's primary critique is that the model is "over-tuned" and possesses a "narrow vision." It excels at latching onto specific, immediate data points (the "forest") but struggles to zoom out and maintain contextual awareness (the "trees"). This limitation was evident in both coding tasks (struggling with code rebase and edge cases) and business strategy (over-rotating on small data points rather than synthesizing a broad, data-anchored strategy).

## Key Points
- **One-Shot Excellence vs. Edge Case Failure:** Opus 4.8 is highly impressive for initial, complex, brand-new feature development (one-shot tasks). However, its performance degrades significantly when the task requires maintaining context, handling existing code structures, or addressing edge cases—the "last 10%."
- **Hallucination and Grounding Issues:** A major concern is the model's tendency to hallucinate or over-rotate on hypotheses rather than being strictly anchored to the provided data or code truth. This was observed even when the model explicitly stated it had not searched external sources (e.g., GitHub).
- **Model Comparison (4.7 vs. 4.8):** In a business strategy test, Opus 4.7 was superior because it was "numbers anchored," structured, and capable of zooming out to put all data into context. Opus 4.8, conversely, was "hand-wavy" and tended to over-rotate on small, isolated data points.
- **Benchmarking Claims:** Anthropic claims Opus 4.8 hits 69.2% on Sweebench Pro, which is reported as being significantly higher than Opus 4.7, GPT 5.5, and Gemini 3.1. (Note: These are manufacturer claims, contrasted with the speaker's personal experience).
- **Efficiency Trade-off:** The model's high efficiency and speed (good ergonomics) appear to come at the cost of deep contextual accuracy and strategic ambition.

## Tools & Resources
- **Anthropic Claude Opus 4.8:** The subject model, best used for initial prototyping and fast, contained tasks.
- **Claude Opus 4.7:** Recommended for complex, high-stakes strategic analysis and tasks requiring deep contextual grounding.
- **CloudCode:** The specific environment used for testing the model's coding capabilities.
- **Anthropic API:** The underlying technology for accessing the model (Note the cost: $5 per input tokens, $25 per million output tokens).

## Action Items
- [ ] **Use for Greenfield Prototypes:** Leverage Opus 4.8 for initial, contained, "one-shot" development tasks where the scope is entirely new and well-defined.
- [ ] **Prioritize Contextual Models for Strategy:** For business strategy, roadmapping, or analyzing existing complex data, continue to favor models (like Opus 4.7, or similar) that demonstrate strong ability to zoom out and synthesize context, rather than just latching onto specific data points.
- [ ] **Treat Output as Hypothesis, Not Fact:** When using any advanced AI model for mission-critical code or business decisions, assume the output is a strong hypothesis that requires manual validation and deep human review, especially regarding external data sources (e.g., "Did it search GitHub?").
- [ ] **Test on Existing Codebases:** Dedicate testing time to using the model on existing, messy, or complex code branches to identify its true limits in real-world development scenarios.
- [ ] **Focus on Prompting Strategy:** Since the model is fast and efficient, focus efforts on developing sophisticated prompting and "harness" strategies to guide it past its tendency to over-rotate on small details.
