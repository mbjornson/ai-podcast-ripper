# The secret to better AI prototypes: Why Tinder’s CPO starts with JSON, not design | Ravi Mehta (product advisor, previously EIR at Reforge) — How I AI

## Summary
The episode challenges traditional product development assumptions that rely on design systems or visual mockups as the foundation for AI prototyping. Ravi Mehta, a seasoned product leader who previously served as CPO at Tinder and worked with major companies like Facebook and TripAdvisor, argues that true efficiency comes from shifting focus to **data structure**. He introduces "data-driven prototyping," a methodology where the prompt is built around defining a concrete data schema (using JSON) rather than describing the desired UI or aesthetic.

The core discussion revolves around moving beyond "vibe coding" or vague prompts—such as "make it look nice"—which often result in average, unoptimized prototypes. Instead, by providing structured input that mimics how engineers think (i.e., defining the data model first), users can force AI tools to generate highly functional, componentized code and mock data sets, effectively accelerating the product development lifecycle from concept to a testable structure.

## Key Points
- **Data Schema > Design:** The foundation of great prototyping should be the underlying data model (JSON schema), not the visual design or UX description. This approach forces the AI to think like an engineer first, making the resulting prototype more functional and flexible for testing different data sets.
- **The Failure of Vague Prompts:** Generic prompts ("make a website for planning a Paris trip") lead to outputs that are "average across those things" because the AI is trying to optimize for design, product, *and* engineering simultaneously without clear constraints.
- **Data-Driven Workflow:** The optimal method involves defining the data structure first: *"Generate a sample itinerary... using JSON."* This approach forces the tool to create not only the UI components but also the necessary underlying mock data (`libmock.ts`), which is crucial for accurate user feedback testing.
- **Accelerated Product Development:** Data-driven prompting acts as an accelerated version of the traditional product development process, allowing PMs and designers to rapidly iterate on complex features (like multi-user trip planning) by focusing on functionality and data constraints rather than visual polish.

## Tools & Resources
- **Reforge Build:** A specific prototyping tool mentioned that is designed for product teams working with established products, noted for generating clean, production-ready code.
- **Google AI Studio / Gemini 2.5 family:** Mentioned as the general platform for building and testing advanced LLM capabilities (Pro for complex reasoning; Flash for performance/price balance).

## Action Items
- [ ] **Master Structured Prompting:** When using any generative AI tool (LLMs, image generators), shift your prompts from descriptive language ("make it look nice") to structured data requirements (e.g., "Using JSON format, generate a schema for X...").
- [ ] **Define the Data Schema First:** Before prototyping a feature, force yourself to write out the required data fields and relationships in a JSON or YAML structure. Use this schema as the primary input prompt for AI tools.
- [ ] **Test Data Integrity:** When reviewing AI prototypes, specifically look for hallucinations (e.g., broken URLs, incorrect geographic locations) and treat them as immediate failure points that require manual correction/refinement of the prompt.
- [ ] **Explore Reforge Build:** If you are in a product role, investigate tools like Reforge Build to see how they handle structured data inputs versus simple text prompts for prototyping established products.
