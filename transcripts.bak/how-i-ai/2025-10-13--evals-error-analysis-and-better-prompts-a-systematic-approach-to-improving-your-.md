# Evals, error analysis, and better prompts: A systematic approach to improving your AI products | Hamel Husain (ML engineer) — How I AI

## Summary
The episode provides a systematic deep dive into moving an AI product from "good" to "great," arguing that quality improvement is fundamentally rooted in rigorous data analysis, not just iterative prompt engineering. The discussion emphasizes that while AI introduces new complexities, the core principles of product development—especially looking at user behavior and metrics—remain paramount. Hamill Hussain, the expert, guides listeners through advanced debugging techniques necessary for managing non-deterministic models.

The central thesis is that developers must stop guessing how users will interact with their AI. Instead, they must adopt an engineering mindset by logging comprehensive "traces" of every interaction. This process allows product teams to analyze not just what the user said, but the entire sequence: the system prompt, the user input, any internal tool calls, and the resulting output—revealing where the AI fails in real-world, messy contexts.

## Key Points
- **The Primacy of Tracing:** To debug complex AI interactions (like chatbots), you must log full "traces." A trace captures every event: the system prompt, user input, internal tool calls, and the resulting output. This holistic view is necessary because fixing one prompt might break another part of the overall workflow.
- **The Value of Messy Data:** The most critical data source is *real user input*. Developers often test with clean, clear questions, but real users provide vague, ambiguous, or poorly phrased inputs (e.g., "What's up?"). Analyzing this messy, natural language distribution is essential for building robust AI systems that handle the real world.
- **Systematic Error Analysis:** Instead of guessing and making isolated prompt fixes, product teams must use data to identify systemic failure points. The example of Nurture Boss showed the AI failing not because it misunderstood a word, but because its default response (promoting special deals) was incorrect given the user's underlying intent (asking about general lease terms).
- **Data Acquisition Methods:** If real-world logging is impossible, developers can use synthetic data generation. However, this must be done carefully; simply generating questions with an LLM often fails to replicate the truly vague or ambiguous nature of human speech.

## Tools & Resources
- **Tracing/Logging Platforms:** Systems like Braintrust (or similar observability tools) are necessary for logging and visualizing multi-turn AI interactions in a structured, traceable manner.
- **SQL Skills:** While the data surface area is broader with AI, foundational skills in writing SQL and performing self-directed data analysis remain "table stakes" for any modern product manager or technical leader.

## Action Items
- [ ] **Develop Observability Skills:** Learn to implement and analyze full interaction traces (System Prompt $\rightarrow$ User Input $\rightarrow$ Tool Calls $\rightarrow$ Output) for any complex system you manage, moving beyond simple error logs.
- [ ] **Prioritize Real Data Collection:** When building or managing a product, dedicate time to analyzing raw, messy user input data rather than just testing with ideal use cases.
- [ ] **Master Ambiguity Analysis:** Practice identifying the *underlying intent* of vague or poorly phrased requests in your industry (e.g., translating "What's up?" into a specific business query).
- [ ] **Strengthen Data Fundamentals:** If you are in product management, dedicate time to refreshing advanced SQL skills and data exploration techniques.
