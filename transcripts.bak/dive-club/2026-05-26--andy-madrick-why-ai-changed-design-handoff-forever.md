# Andy Madrick - Why AI changed design handoff forever — Dive Club

## Summary
The episode details how AI is fundamentally redefining the design workflow, particularly the handoff process from design concept to production code. Andy Madrick, who leads design for Notion Meeting Notes, outlines a highly advanced, iterative process that leverages AI tools to drastically accelerate development. His core argument is that while LLMs and coding tools can handle the bulk of the execution (up to 80-90% of the front end), the designer's superpower must now be owning the "last mile of craft"—the outcome, the user experience, and the detailed descriptive vision.

Madrick's workflow is a blend of traditional design (Figma) and modern, code-based prototyping (Notion's playground). He uses tools like Paper (a snapshot tool) and LLMs to rapidly iterate on components by feeding them real HTML/CSS, allowing for seamless concept generation. The most significant shift discussed is the ability to take a functional prototype directory, feed it to an LLM, and have it "one-shot" the translation into flawless production code, eliminating much of the traditional engineering friction.

## Key Points
- **The Designer's New Superpower:** The value is no longer in pixel-pushing or manual component creation, but in defining the *outcome* and the *user experience*. Designers must be responsible for the entire change, not just the visual mockups.
- **The 80/20 Rule of AI Handoff:** AI tools are capable of building 80-90% of the front end, but the remaining 10-20%—the unique polish, the emotional connection, and the final refinement—is the designer's domain.
- **Code-First Iteration:** The workflow is migrating from pure Figma mockups to code-based prototypes (like Notion's playground). This allows for a higher fidelity of feedback and enables content teams to co-design within a functional, editable context.
- **AI-Powered Component Snapping:** Tools like Paper (a Chrome extension) allow designers to copy any component from a live website and paste it into an editable canvas using real HTML and CSS, making the design process feel like the future.
- **AEO Readiness is Critical:** Websites must be "AI readable" to maintain visibility. Framer's AEO tool scores sites on how well AI systems understand and index the content, providing actionable steps to improve SEO visibility in the age of AI.
- **The Power of Visual Description:** When dealing with complex motion design, a picture (screenshot) fed to an LLM is often more effective than thousands of words of text, as it provides the necessary visual keyframes and context for the AI to execute.

## Tools & Resources
- **Notion Prototype Playground:** A lightweight, internal version of the Notion codebase used for creating highly functional, editable prototypes that allow for co-design and testing before production.
- **Paper:** A Chrome extension that allows users to copy any component or element from a live website and paste it into an editable canvas as real HTML and CSS layers.
- **Framer AEO Tool:** A free tool (framer.com/AEO) that scans a website and scores its "AI Entity Optimization" (AEO) readiness, identifying structural issues that hurt visibility in AI search systems.
- **LLMs (Claude/ChatGPT):** Used not just for text generation, but for code translation, component spinning, and taking visual descriptions (screenshots) and turning them into functional code concepts.

## Action Items
- [ ] **Develop Descriptive Prompting Skills:** Practice taking complex visual ideas (e.g., animations, component states) and translating them into highly specific, multi-step visual prompts (screenshots, keyframes) for LLMs, rather than vague text descriptions.
- [ ] **Master Code-Based Prototyping:** Move beyond static Figma mockups. Learn to build prototypes using code-based playgrounds (or similar tools) to simulate real-world component behavior and allow for functional co-design.
- [ ] **Audit Website AEO:** Use Framer's AEO scanner on your own website or client sites to understand how AI systems are currently reading and indexing your content, and implement structural fixes immediately.
- [ ] **Experiment with Component Snapping:** Try using tools like Paper to copy live web elements into an editable canvas, simulating the process of building a design using real-world, production-grade components.
- [ ] **Shift Focus from Pixels to Principles:** When starting a project, spend more time defining the desired *user outcome* and *business goal* (the "why") before designing the visual elements (the "what").
