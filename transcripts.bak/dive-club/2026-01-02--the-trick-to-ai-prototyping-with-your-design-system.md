# The trick to AI prototyping with your design system — Dive Club

## Summary
The episode details how established companies, specifically Atlassian, are scaling AI-powered prototyping beyond simple ideation. The core challenge discussed is moving from initial, low-fidelity AI prototypes to high-fidelity, consistent experiences that feel like a native product. The design system's role has dramatically expanded from merely enforcing visual consistency to becoming the foundational scaffolding that allows *anyone* in the organization to "ship" a coded prototype.

The solution involves creating "abstracted templates" within tools like Figma Make. These templates are not specific products but rather pre-coded baselines that lock down the most difficult-to-replicate UI elements—like the top navigation and side navigation. By providing this stable starting point, the system significantly reduces the AI's tendency to "hallucinate" or misrepresent core product elements, allowing users to focus on the unique content and functionality rather than the shell.

## Key Points
- **Shift from Creation to Modification:** The most significant finding is that having the AI *modify* existing, pre-coded elements (like updating a sidebar component) is vastly superior to asking the AI to build an entire complex UI from scratch. This approach drastically reduces the error rate.
- **The Power of the Abstracted Template:** Templates are designed to be non-product-specific scaffolding. They ensure that critical, high-fidelity components (like the Atlassian top nav) remain consistent, even when the user is prototyping a completely new feature (e.g., a roadmap).
- **Error Reduction Metric:** The implementation of these templates reportedly reduced navigation-related errors from an estimated 50% of prototypes to near zero, solving a major pain point for user testing and design reviews.
- **Hybrid Approach for Reliability:** The system combines pre-coded design system instructions with user-friendly, copyable commands (e.g., clicking a button to copy a logo constant) to mitigate the AI's reliance on outdated or incorrect pre-trained knowledge.
- **Modularization via "Recipes":** For advanced use cases (like adding a chat box component to an existing prototype), the team introduced "recipes"—small, self-contained code blobs with instructions—to avoid the cumbersome process of duplicating entire templates.

## Tools & Resources
- **Figma Make / Replit:** The primary tools used for running and generating the coded prototypes.
- **Design System:** The foundational element; it provides the structured, pre-coded components (e.g., Top Nav, Side Nav) that the AI references.
- **Raycast:** (Mentioned in the ad) A highly recommended productivity tool/extension for maximizing computer efficiency.
- **Genway AI:** (Mentioned in the ad) A platform for conducting virtual, AI-driven customer interviews for rapid idea validation.

## Action Items
- [ ] **Develop a "Scaffolding First" Prototyping Workflow:** When prototyping, prioritize locking down the core, high-fidelity shell elements (navigation, headers) using a design system before adding unique content.
- [ ] **Implement Modular Component Libraries:** Instead of building full, monolithic templates, create small, reusable "recipes" or code snippets for common, complex components (e.g., chat widgets, specific data tables) to improve iteration speed.
- [ ] **Audit AI Prompting for Consistency:** If using generative AI for UI, test the model's ability to maintain brand consistency on critical elements (logos, navigation) and build guardrails (hard-coded constants) to override general AI knowledge.
- [ ] **Adopt a Productivity Launcher:** Investigate tools like Raycast to streamline workflow and reduce cognitive load associated with repetitive computer tasks.
- [ ] **Practice "Validation-First" Thinking:** Before building a feature, use AI-driven methods (like Genway AI) to validate the core problem and user need with a defined Ideal Customer Profile (ICP).
