# Geoffrey Litt - The Future of Malleable Software — Dive Club

## Summary
The episode explores the imminent "platform shift" in software design, driven by the volatility and capabilities of Large Language Models (LLMs). Jeffrey Litt, a design engineer at Notion, argues that traditional Software-as-a-Service (SaaS) models—where companies dictate rigid workflows within siloed applications—are reaching an inflection point. His career journey revealed this flaw: users often bypass polished corporate tools by exporting data to spreadsheets because the spreadsheet grants them ultimate control and malleability over their workflow, regardless of how "ugly" it is.

Litt's core thesis centers on moving from *app-centric* design (where the app dictates the process) to *document-centric computing*. This new paradigm envisions a software operating system where functionality—like weather data, maps, or calculations—is seamlessly pulled into and lives within a single document (a "note"). The goal is to create personalized, malleable software that users can bend and shape over time, rather than being forced to fit the product's pre-defined structure.

The discussion highlights how AI is accelerating this shift. Instead of merely asking an LLM for a number ("How much money will I have?"), the future requires interactive data visualizations and functional components embedded directly into the user’s working document, allowing them to manipulate the output in real time.

## Key Points
- **The Failure of Siloed Apps (The "Embark" Problem):** Modern life requires combining disparate services (Google Maps, Notion, Calendar, Email). Current apps are designed as isolated units, leading to frustrating gaps where data must be manually transferred or synchronized. The solution is not a "mega app," but a system that allows functionality to live *within* the user's primary workspace (the document).
- **The Power of User Control:** Litt notes that users often prefer using basic tools like Excel spreadsheets for complex tasks because they provide absolute control over data organization and process, even if those tools are buggy or aesthetically poor. This demonstrates a fundamental need for malleability that polished SaaS products fail to meet.
- **Document-Centric Computing is the Next OS:** The future of productivity software is not about building more features into an app; it's about making the document itself the core operating layer. Functionality (AI, APIs, calculations) must be embedded directly into the note, allowing the user to "pull in bits of functionality" as needed.
- **The AI Interaction Pattern Shift:** The shift is moving from text-based Q&A ("Ask ChatGPT...") to interactive data visualization and manipulation. The goal is for the AI output to be a dynamic element within the document that can be messaged with, not just a static number or paragraph.

## Tools & Resources
- **Notion:** A platform positioned as an early leader in document-centric computing; it serves as the primary example of malleable software where users build and customize their own systems.
- **Granola:** Mentioned for its "recipes" feature, which allows advanced prompts to run across all context within a user's notes—a key productivity tool for synthesizing information from large knowledge bases.
- **Lovable Cloud / Lovable AI:** A development resource that enables users/designers to build full-stack, AI-native applications simply by prompting, bypassing the need for manual setup of databases, authentication, or API keys.

## Action Items
- [ ] **Develop Systems Thinking:** When building or designing any process, identify the points where data must be manually transferred between two separate applications (the "friction points"). These are opportunities for a new integrated platform.
- [ ] **Experiment with Document Tools:** Use Notion or similar knowledge management tools not just for storage, but as the primary engine for complex workflows. Try to embed calculations, databases, and external information sources directly into your notes.
- [ ] **Explore AI Prompt Engineering for Synthesis:** Utilize advanced prompting techniques (like those mentioned in Granola's "recipes") to force LLMs to synthesize actionable themes and direct quotes from large bodies of unstructured text (e.g., user interviews).
- [ ] **Focus on Malleability over Polish:** When evaluating existing software solutions, prioritize tools that allow for deep customization and data manipulation by the end-user, even if the interface is less polished than a dedicated corporate app.
